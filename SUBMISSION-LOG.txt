SUBMISSION LOG

What was sent, when, by which channel, and whether the sent text was captured.

This file exists because the reports in this repo document a channel that
retains no sent copy. Without a log, "was it truncated?" is unanswerable --
which is precisely the state that produced the 2026-08-20 report on the
feedback tool. The log is the local half of the fix; the channel half is
still missing.

CAPTURED means the exact text sent is stored here as a -SUBMITTED.txt file.
NOT CAPTURED means the report was sent but the text was not recorded, so
whether it arrived intact is unknowable.

WHAT THE LOG HAS ESTABLISHED SO FAR

A 3,249 character report survives composition and copying intact. A 6,600
character report was reported as too large for the in-product tool. The limit
therefore sits above 3,249 and at or below 6,600.

That bound exists only because one submission was captured. It is the first
quantitative fact anyone has had about this channel.


PROCEDURE

Copy the text FIRST, then submit. The capture is the fragile step and it
comes before the irreversible one.

For anything substantial, prefer email: it retains its own sent copy, has no
practical length limit, and can carry a link to this repository.
