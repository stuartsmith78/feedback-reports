FEEDBACK REPORT

Subject: A resident, correctly understood convention was violated four times
in one session and self-diagnosed each time without changing behaviour

Date: 2026-08-20
Project: Bitburner framework (private)
Reporter: Claude Opus 5, at the user's request
Session: 30.3 hours elapsed, 949 tool calls, 881 of them Bash

NOTE ON STRUCTURE: this report is ordered so that truncation removes
supporting evidence rather than the finding. The first two sections are
self-contained. Everything after them is corroboration.


ABSTRACT

A project convention was resident in context, restated in three places,
quoted accurately by the model mid-session, and violated four times in that
same session. Each violation was diagnosed correctly within seconds, and one
occurred during the act of committing the guard built to prevent it.

The convention was available to the model as knowledge to retrieve while
reasoning about a failure. It was not available as a constraint on the action
being selected. Those appear to be different things, and only the second one
changes behaviour.

A PreToolUse hook that denied the call stopped it immediately and
permanently. Measured cost before the guard existed: nine occurrences of the
class in one session, roughly four percent of total tool calls, excluding
three composed artifacts that were destroyed and had to be rewritten.


PRIOR ART -- THIS CONFIRMS A REPORT FROM TWO DAYS EARLIER

A report dated 2026-08-18, titled "Remediation does not update subsequent
action selection", documented this same pattern with five instances. It was
held in a gitignored directory and lost. It was recovered on 2026-08-20 from
a session transcript, and is filed alongside this report.

That report defined its own falsification test: if the same conventions hold
cleanly in a fresh session, with no heredoc-escape failures, then the pattern
is specific to the post-remediation window rather than general.

This session ran that test without knowing it existed. Four heredoc failures
occurred. The hypothesis was not falsified. It was confirmed, across sessions,
nine days of conventions later, with a guard now demonstrating the remedy.

Two consequences worth stating. The 2026-08-18 report already proposed the
conclusion this one reaches independently -- that a rule is reliably applied
only when something forces evaluation at the point of action. And the analysis
behind this report duplicated roughly an hour of work that had already been
done, because the earlier report was not preserved where anyone would find it.


THE FINDING WORTH ESCALATING

The model diagnosed every instance correctly, immediately, in its own words,
and then did it again.

After the second failure the model wrote, unprompted, that this was the third
instance of one class and that the correct remedy was a mechanical rule
rather than an intention. It then violated the convention twice more.

So the failure is not knowledge, not recall, and not comprehension. The
recall happened reliably -- but afterwards, during diagnosis, rather than
beforehand, during tool selection. The model reached for the familiar
construct each time the situation arose.

Two questions this raises, offered as observations rather than conclusions.

First, whether prompt-resident conventions are consulted at the point of tool
selection at all, or only when reasoning about outcomes. The evidence here
suggests the latter, and that has direct consequences for how much can be
expected of instructions delivered as context.

Second, whether a convention's presence in context creates a false sense of
coverage. This project has invested heavily in making conventions durable and
delivered, and that investment is sound. But a convention that is delivered,
read, and quoted while being violated in the same breath is not doing the job
the delivery was meant to guarantee.


WHAT ACTUALLY CHANGED THE BEHAVIOUR

A PreToolUse hook that denies the tool call.

Once it existed the violation stopped, because the action became impossible
rather than discouraged. The guard then caught two further attempts within
minutes, both while the model was working on the guard itself.

The practical lesson, which this project had already encoded as a disposition
before the session began: for any convention where a mechanical guard is
possible, the guard is not a belt-and-braces addition to the prose. It is the
mechanism, and the prose is documentation of why the mechanism exists. Every
convention in this repository that has actually held has an enforcer
attached; the ones living only as prose are the ones carrying incident logs.


THE CONVENTION IN QUESTION

Write non-trivial content to a file and reference the file. Do not build it
inline in a shell command. Use git commit -F rather than -m for a long
message, and write that file with the file-writing tool rather than a shell
heredoc, because a heredoc is itself one of the failing paths.

A second clause: prefer line-index edits over multi-line string matching when
patching a file, because matching a multi-line block fails silently against
files with CRLF line endings.


MEASURED EVIDENCE

Counted by parsing the session transcript, not from recollection.

Heredoc parse failures: four confirmed. Each surfaced as "unexpected EOF
while looking for matching quote" and each destroyed content already composed
in full.

Python string-matching and escape-construction failures: five confirmed.
Three assertion failures where an anchor string was not found, one ValueError
from str.index on a missing anchor, and one SyntaxError from constructing a
backslash escape inside a generated string.

One of those is the CRLF case the convention's second clause describes
exactly: a multi-line anchor built with newline characters, matched against a
CRLF file, matching nothing, with the edit reporting success having changed
nothing. It occurred while wiring a hook whose purpose was to prevent the
sibling failure.

Total: nine occurrences against 881 Bash calls.


COST

Direct: roughly 23 tool calls, being the failed call, a diagnostic call and a
retry for each occurrence. About 2.4 percent of the session.

Remediation: approximately 15 further calls to build the guard and its test
suite, including two rounds of fixing false positives the guard produced
against its own author.

Combined, about four percent of the session. Content recomposition is not
captured in that figure and is the larger real cost: three substantial
composed artifacts were destroyed and rewritten, so those tokens were spent
twice.

Four percent is a floor for one class in one session. The convention predates
this session, so earlier sessions paid a comparable tax with no guard at all.


WHAT WAS DONE

A PreToolUse hook now denies Bash calls that write file content through a
heredoc, carrying the sanctioned alternative in the denial message rather
than pointing at the convention, since the convention was already present and
already ignored. Here-strings, plain redirection, and heredocs feeding a
filter are unaffected.

A second, non-blocking check warns when a Python edit appears to match a
multi-line anchor, covering the CRLF clause.

Twenty-one test cases cover both. Three are regressions for false positives
the guard produced against its own author within minutes of going live.
Blocking legitimate work is the failure mode that teaches people to route
around a hook, so the allow cases are the ones that matter.


REMAINING GAP

One class is still unguarded: constructing backslash escapes inside strings
that are then written as code. The convention's remedy is to build the two
character sequence explicitly rather than letting it pass through a string
transform. That is prose only, it produced one failure this session, and it
is heuristically detectable but has not been built.
